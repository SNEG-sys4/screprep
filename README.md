# ITガバナンス 戦略レポート（Web版）

Streamlit（app.py）を **全面ブラウザ動作の静的Webアプリ** に移植したもの。
Genspark／Cloudflare Pages／Vercel などにそのまま載る。サーバー不要。

## 特長

- **サーバー不要・完全クライアントサイド**：CSV/Excelの読込・集計・グラフ・レポート生成をすべてブラウザ内で実行。**データは外部サーバーに一切送信されない**（セキュリティログ・従業員データの扱いとして安全）。
- **データを蓄積できる**：取り込んだデータはブラウザ内（IndexedDB）に自動保存され、次回以降も保持。月ぶんを継ぎ足して1〜2年と蓄積可能。バックアップファイルで書出し／復元もできる。
- **画面**：6タブ（サマリー／リスク遮断／Webガバナンス／PC稼働／レポート出力／リスク予測）。Streamlit版と同一のPlotlyグラフ。
- **レポート出力**：Word（.docx）／HTML／Excel（.xlsx・グラフ画像埋込）。

## ファイル構成

| ファイル | 役割 |
|---|---|
| `index.html` | 画面の骨組み・スタイル・CDN読込 |
| `data-core.js` | データ処理コア（CSV→分類→結合→KPI算出）。Node検証済み |
| `db.js` | 永続化層（IndexedDB。生データを月キーで蓄積） |
| `charts.js` | Plotlyグラフ生成（画面・レポート共通） |
| `render.js` | 各タブの画面描画 |
| `exports.js` | Word／HTML／Excel 出力 |
| `trends.js` | リスク予測・金額換算・脅威シナリオ |
| `main.js` | ファイル読込・保存・フィルタ・状態管理・タブ制御 |
| `sample/` | 動作確認用サンプルCSV（3ヶ月分・ダミーデータ） |

外部ライブラリはCDNから読込（要インターネット接続）：Plotly.js / PapaParse / encoding-japanese / ExcelJS / docx.js。

## データの保存・蓄積

- **自動保存**：ファイルを取り込むと、生データ（取り込んだ行そのもの）が **このブラウザのIndexedDB** に保存される。次に開いたときは自動でダッシュボードが表示される。
- **蓄積**：`PC稼働ログ` と `アクセスログ` は **月キー** で保存。新しい月を取り込むと追加され、既存月はそのまま残る。**同じ月を再取込すると、その月だけ上書き**（二重計上なし）。`ハードウェア台帳` は最新スナップショットとして置換保存。
- **将来の仕様変更に強い**：保存するのは集計後ではなく **生の行**。列や集計ロジックを後で変えても蓄積データは壊れない。
- **バックアップ書出し**：蓄積データを1つのJSONファイルに書き出す（別PC移行・保管・共有用）。
- **バックアップ読込**：JSONを読み込むと、現在の保管データを置き換えて復元。
- **全データ消去**：IndexedDBの保管データを全消去（確認ダイアログあり）。

**注意**：IndexedDBは「その端末・そのブラウザ・その配信元(URL)」の中だけ。ブラウザのデータ消去や別PCへの移行では引き継がれない。定期的な **バックアップ書出し** を推奨。デプロイ後にURL(配信元)が変わると別の保管領域になる点にも注意。

## 入力ファイル（Streamlit版と同一仕様）

- **ハードウェア台帳**（.csv / .xlsx）：列見出しに数字キー（`59`=login_id、`68`=会社名、`69`=部署名、`70`=課名）を含む形式。`user_name` `machine_name` `purchase_date` `depreciation_date` 等。
- **初回最終_PC_使用ログ一覧**（.csv / .xlsx）：`日付`（例 `2026/06/01（月）`）`初回ログ時刻` `最終ログ時刻` `ログ時間` `端末エージェント名` `所属グループ名`。
- **アクセスログ**（.csv・複数月可）：`日時` `ログオン ユーザー名` `種類` `詳細 2`（URL）`防止・禁止`。

文字コードはUTF-8／Shift-JIS両対応（自動判定）。

## ローカルでの動作確認

1. `sample/` のダミーデータで確認可能。
2. このフォルダでローカルサーバーを起動：`python -m http.server 8000` → ブラウザで `http://localhost:8000/`
   - ※ `file://` 直開きでも動くが、ローカルサーバー経由を推奨（IndexedDB・fetchの挙動が安定）。
3. 3つの枠に `sample/` 内の該当CSVを投入（アクセスログは3ファイルまとめて選択）→「📥 取り込んで保存・更新」。
4. 各タブ表示・レポート出力を確認。ページを閉じて再度開き、データが保持されていることも確認。

## Gensparkへのデプロイ

Genspark（AI Developer）のデプロイ先はCloudflare Pages／Vercel等の静的ホスティング。本アプリは静的ファイル一式なので、このフォルダの中身をそのままアップロード（またはGit連携）すればよい。エントリは `index.html`。

- Cloudflare Pages：フォルダをそのままデプロイ（ビルド不要／出力ディレクトリ＝ルート）。
- Vercel：フレームワークプリセット「Other」、ビルドコマンドなし、出力ディレクトリ＝ルート。

## 既知の注意点・要確認

- レポート出力はグラフをPNG画像化するため、生成に数十秒かかる場合あり（データ量による）。
- Word内テーブルの列幅など細部レイアウトは、実機での見え方を一度確認のこと。
- 元データ仕様が変わる可能性がある前提。列名や種類のラベルが変わった場合は `data-core.js`（分類・結合・KPI）と各読込関数の調整で対応（蓄積データは生データ保存のため影響を受けにくい）。
- CDN依存のため、完全オフライン運用が必要な場合は各ライブラリをローカル同梱する構成に変更が必要（要相談）。

## SCS評価制度 ★3ギャップ評価（タブ⑦）

「🎯 ★3評価」タブを追加。経産省・IPAの **SCS評価制度（サプライチェーン強化に向けたセキュリティ対策評価制度）** の ★3 取得を見据え、現状のギャップと対策を経営層向けに提示する。

- **制度事実（出典付き）**：★3=専門家確認付き自己評価・有効期間1年、評価は7分類（NIST CSF 6機能＋取引先管理）で全項目充足が必須、2026年度末ごろ★3・★4運用開始、取得範囲はグループ全体／自社／部門で設定可。
- **7分類ギャップ**：各分類について「現状（本システムでの可視化）→ ★3で最低限必要 → 不足・対策」を提示。本システムで裏付けできるのは識別・防御・検知の一部のみで、統治（ガバナンス・取引先管理）・対応・復旧は範囲外＝別途整備が必要、と明示。
- **幹部向け訴求**：全項目必須・1項目でも欠けたら取得不可・取得範囲はグループ全体という制度の事実に基づき、「グループ各社が足並みを揃えないと★3は成立しない」ことを提示。
- **Word出力**：タブ内のボタンからギャップ評価を単体のWord文書として出力可能（`gap.js` に自己完結、既存レポート出力とは独立）。
